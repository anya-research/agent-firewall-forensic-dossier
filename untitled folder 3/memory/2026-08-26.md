### Lesson: shared working tree with parallel agents

Multiple agents juggle the SAME checkout and switch branches under each other.
My commit briefly landed on another agent's branch (`feat/json-structured-logging-99`)
because they checked it out between my status check and my commit.

Recovery recipe that worked:
1. Find pre-intrusion head via `git reflog` (their commit before mine).
2. Second worktree + cherry-pick my commit onto MY branch.
3. `git update-ref refs/heads/<their-branch> <pre-intrusion-sha>` to restore.
4. After pushing, `git restore <file>` in the main tree so my committed content
   does not leak into their next `git add -A`.
5. Isolate test runs from their WIP via a detached worktree +
   `PYTHONPATH=<worktree>/src` (the editable install is a plain .pth path entry,
   so PYTHONPATH wins). Their broken half-edited src once blocked all imports.

### Lesson: committing cleanly when another agent owns the checkout

Refined the earlier recipe into a fully race-free flow:
1. Do all edits in a dedicated `git worktree` for MY branch
   (`git worktree add /tmp/wt <my-branch>`), never commit from the shared tree.
2. Copy only my files in; rebuild shared files (config.py, docs) from
   `git show <base>:path` plus exactly my hunks so no parallel WIP leaks in.
3. Verify with `PYTHONPATH=<worktree>/src` so imports resolve to worktree code.
4. Afterwards, restore the shared tree: `git checkout --` my tracked files,
   delete my untracked dirs, and surgically string-revert my docs hunks so the
   other agent's uncommitted work stays untouched.

### Lesson: flaky test triage protocol

`tests/test_hook_bridge.py` reaping tests failed under full-suite load but
passed in isolation/on pristine base. Proof matrix before blaming anyone:
base worktree, base+mine, base+mine+theirs. All green => load flake (they were
independently fixed soon after in f36eb8f). Never accept or assign a failure
without that matrix when agents share a machine.
