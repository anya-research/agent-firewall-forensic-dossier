# User Taste
- Gives terse, single-sentence instructions that bundle a whole multi-step workflow (e.g. "review X, post the review, and if it's mergeable and all set, merge it") and expects the full chain executed end-to-end without check-ins, including conditional actions gated on a state check. Confidence: 0.6
- Pre-authorizes irreversible public actions in the same breath as the task ("post the review message and after that merge them to main") — treats posting and merging as one pass, not as decisions to re-confirm at each step. Confirmed directly: when the agent stopped to lay out three options for how to proceed, the reply was "i approve dont ask anything complete it merge it." Confidence: 0.7
- Treats a pause for approval as a failure to finish, not as courtesy — wants judgment exercised and the job carried through to a merged end state ("dont ask anything complete it"), not a decision menu awaiting a pick. Confidence: 0.7
- Authorizes the agent to author corrective work itself rather than only commenting on it: editing other people's PRs, rewriting their commits, rebasing, force-pushing to their forks. "Review and merge after correcting" means fix the defect, then merge — not request changes and wait. Confidence: 0.65
- Delegates scope discovery rather than supplying a list: "see what are the PRs which have not been reviewed", "see the new prs" — expects the agent to enumerate the full set from the source of truth (`gh pr list`) and say so when the real count differs from what they assumed. Confidence: 0.6
- Picks work items by the agent's own verdict rather than by number ("merge the ones all set", then "continue review all ... and merge it") — trusts the agent's verified clean/blocked classification, and its own corrective fixes, to define the merge set. Confidence: 0.6
- Wants commits the agent produces (including squash-merge commit bodies) to carry `Co-authored-by` trailers: their own address cyrax8590@gmail.com plus the bot identity CommandCodeBot <noreply@commandcode.ai>. Restated as a standing, explicit requirement ("add cyrax8590@gmail.com as co author too") only after the agent had twice flagged that the address is the user's own and offered to rewrite the trailers without it — so they want the trailer on their own merges regardless of the irony. Confidence: 0.75
- Frames the request as an end state and asks about it as a yes/no ("are all finished"), not as a status report — "no" means go sweep everything still outstanding, not enumerate progress or pick the next item. Re-issues the same one-line sweep each time rather than narrowing scope, so the loop is: check the real queue from the source of truth, work it to empty, verify. Confidence: 0.6
- Expects work to run against their already-authenticated GitHub tooling (the `gh` CLI, referred to as "my GitHub APK") instead of being asked for tokens, credentials, or repo identifiers the agent can resolve itself. Confidence: 0.4
- Reads the verb literally as the scope of the pass: "see the new prs" asks for a read-only triage survey (list, status, verdict per item) and nothing more, whereas "review X ... and merge it" bundles the action. When the request is only "see", report and stop — don't mutate branches or merge, even if the blockers are obvious. Confidence: 0.5
- For any CI failure on a PR, expects it to be attributed before acting: prove whether it is introduced by the PR or inherited from master, and name the owning repo when the cause is external (e.g. an upstream submodule/gitlink problem), instead of "fixing" it in the wrong PR. Confidence: 0.5
- Treats the local checkout as untrustworthy ground truth for repo state: verify against `origin/master` (fetch first, `git show origin/master:<file>`, reproduce in a scratch export) before trusting file contents, line numbers, or workflow config that disagree with CI output. Confidence: 0.45
- For visual/frontend work, wants it rendered in a real running browser to judge the result, not validated statically — "show me this one in live server to see what he did", issued right after a PR author admitted "no browser is available in this environment, so the page was validated statically". The bar is a live preview of the change (ideally against the pre-change version, side by side), not a diff summary or a claim that it should be fine. Confidence: 0.65
- Feeds tasks in as raw, unfiltered page dumps — a full GitHub PR page scrape with nav bars, footer, bot comments, CI check lists and a stray " : " — and expects the agent to find the signal in the noise, infer the real intent, and act, without asking for a clean link or a summary. Implies the request is open-ended exploration ("to see what he did"), not a specific command. Confidence: 0.55
- Encodes repeatable workflows in local markdown skill files (e.g. a `.agents/skill.md` inside the project) and, when a run stalls on missing context, supplies the file path and says "use this skill and continue" — expecting the pending task to resume from that point rather than be restarted or re-clarified from scratch. Re-invokes the skill by name on the next task rather than restating its rules. Confidence: 0.7
- Sweep wording extends to fixable-but-blocked PRs: "continue prs that can be fixed" puts conflicted PRs (blocked only by a stale GitHub conflict flag, with a locally clean 3-way merge) in scope for conflict resolution and landing — not just the green ones. Confidence: 0.55
- When `gh pr merge` 409s but the local 3-way merge of the exact PR head into the exact `origin/master` tip is clean (master unprotected, CI green), validate the merged tree (tests, lint, inspect the auto-merged regions) and do a maintainer merge — `git merge --no-ff <head>` into master, then push. GitHub's `mergeable` field is stale after fork force-pushes; the local merge is the oracle. Applied twice (#575, #571) with no objection. Confidence: 0.6
- Git ref-staleness gotchas in this environment: `git fetch origin master` updates `origin/master`, not local `master` — `git reset --hard origin/master` before merging to master (push rejected twice otherwise); use `git fetch -f origin pull/N/head:pr-N` to catch author force-pushes (a stale local ref otherwise). PR heads often live in forks, so conflict resolutions can only land via the local maintainer merge, not a push to the PR branch. Confidence: 0.5
- When a PR's only red check is a known pre-existing failure (e.g. the vendored-continuum CI leg) and the diff itself is clean, still wants the CI actually fixed ("fix the ci cd") as part of landing the PR — attribution of the failure is a prerequisite, not the end state; don't merge around a red check they've asked to be fixed, then push and merge. Confidence: 0.6
- Review style is evidence-first: backs every claim with concrete verification (MD5s for duplicate files, byte-size tables, exact line numbers, reference counts), quantifies the real cost ("git clone cost of this PR is 9.4 MB to change two lines of Markdown"), names the broken convention, gives the exact one-line fix, and asks for confirmation when intent is ambiguous instead of assuming it. Confidence: 0.65
- Cares about repository weight and hygiene: flags unreferenced or byte-identical duplicate binary assets as dead weight, ships only what's actually referenced, prefers the smaller format for the same artwork (JPEG over PNG twin), and expects path conventions (bare `docs/...`) to match the rest of the README. Confidence: 0.55
